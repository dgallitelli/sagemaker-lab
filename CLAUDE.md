# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Purpose

Fine-tune a SPLADE sparse embedding model (SentenceTransformers v5 SparseEncoder) on the Amazon ESCI benchmark using ANCE hard negative mining, targeting performance above BM25 baseline. Runs entirely on AWS SageMaker.

## Project Structure

```
prepare_dataset.py          # Download ESCI, build corpus, compute BM25 baseline
deploy_endpoint.py          # Deploy trained model to SageMaker TEI endpoint
aws_blog_post.md            # Publication-ready AWS blog post (fill in result placeholders)
final_results.json          # Populated after training + evaluation
data/                       # Generated by prepare_dataset.py
  train.jsonl
  test.jsonl
  corpus.jsonl
  bm25_baseline_results.json
splade-ecommerce/           # SageMaker training job artifacts
  train.py                  # Entry point (SageMaker + local mode)
  ance_miner.py             # ANCE hard negative mining via Qdrant in-memory
  evaluate.py               # NDCG@10 / Recall@100 / MRR@10 evaluation
  sagemaker_launcher.py     # Launch job or run locally with --local
  config.yaml               # Hyperparameters
  requirements.txt
```

## Execution Order

```bash
# 1. Prepare data and establish BM25 baseline
python prepare_dataset.py --output-dir data/

# 2. Verify end-to-end pipeline locally (no AWS needed)
cd splade-ecommerce
python sagemaker_launcher.py --local --data-dir ../data

# 3. Submit SageMaker training job (spot, ml.g5.12xlarge)
python sagemaker_launcher.py --s3-bucket <bucket> --data-prefix splade-esci/data

# 4. Deploy trained model to endpoint
python deploy_endpoint.py --model-artifact s3://<bucket>/splade-training-output/model.tar.gz

# 5. Cleanup endpoint when done
python deploy_endpoint.py --endpoint-name splade-esci-endpoint --delete
```

## SageMaker SDK v3

Always use v3 — see global `~/.claude/docs/sagemaker-v3.md`. Key imports:
```python
from sagemaker.train.model_trainer import ModelTrainer
from sagemaker.train.configs import InputData, Compute, SourceCode, OutputDataConfig
from sagemaker.core.helper.session_helper import Session, get_execution_role
from sagemaker.core.image_uris import retrieve
```
- `SourceCode(entry_script="train.py", ...)` — NOT `entry_point`
- `ModelTrainer(role=role, sagemaker_session=session, ...)` — role/session on ModelTrainer
- `trainer.train(..., wait=True, logs=True)` — `wait`/`logs` go on `train()`, NOT `ModelTrainer()`
- `output_data_config=OutputDataConfig(s3_output_path=...)` not `output_path=`
- **SDK v3.4.1 bug**: `get_training_code_hash()` crashes when `requirements` is a str. Patch applied in `sagemaker_launcher.py` before job submission. Bug tracked: https://github.com/aws/sagemaker-python-sdk/issues/5518

## Key Design Decisions

- **Qdrant always in-memory**: `QdrantClient(":memory:")` — no external connections, no cleanup needed
- **Local mode**: `sagemaker_launcher.py --local` works without AWS credentials; truncates dataset to 500 train / 100 test / 5000 corpus via env vars
- **CloudWatch metrics**: `train.py` logs `{"metric_name": "...", "value": ...}` JSON to stdout; parsed by metric_definitions in launcher
- **BM25 baseline**: `bm25_baseline_results.json` is the ground truth; `evaluate.py` and `deploy_endpoint.py` both load it for delta computation
- **Blog post placeholders**: `aws_blog_post.md` contains `{ndcg_delta}` etc. — fill from `final_results.json` after training

## AWS Conventions

- Always clean up endpoints: `python deploy_endpoint.py --endpoint-name <name> --delete`
- Spot instances enabled by default in launcher (max_wait=7200s)
